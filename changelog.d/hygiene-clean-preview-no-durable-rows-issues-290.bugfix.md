The `hygiene clean` preview no longer writes durable hygiene-log rows, so its zero-writes promise now matches what it actually does. The preview also no longer reports actions for items already discarded or archived; it reports what would happen only for targets that still need it. The `would_flag`/`would_archive`/`would_discard` counters now carry one meaning in every `hygiene clean` response: on a confirmed run each equals the applied count for its action, matching the preview count. A confirmed `hygiene clean` now records the supplied `reason` and `note` in each durable log row's detail, so the audit row shows why the action was taken. The `--action keep` value is renamed to `apply_suggested` so the name says what it does, and a confirmed `apply_suggested` run now skips a candidate whose own suggestion is `keep` (reported as `skipped`) instead of refusing the whole batch, so the other candidates still apply.
