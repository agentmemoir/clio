Importing a bundle into a bank that does not already hold its items now re-keys each imported id as `{id}#{target-bank}` instead of failing with `invalid_argument: duplicate item id`, so the same bundle file can seed a second bank; the ids reported in `created_ids`, and those of the triples, tasks, and failure rows restored with them, carry that bank-qualified form, while importing into the bank the bundle was exported from is unchanged and keeps every original id.
