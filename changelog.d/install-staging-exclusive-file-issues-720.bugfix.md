The installer now creates its staging file with `mktemp` in the destination directory instead of writing the binary to the fixed name `.<binary>.new` and renaming that, and it refuses an install directory that group or other can write to. Before this change, another local account able to write that directory could plant a symbolic link at the fixed name, and `cp` and `chmod` followed it: whoever ran the install then overwrote the linked file with the binary and widened its mode to 755, and the final `mv` took the link away, so nothing in the install directory showed what had been written. A directory that group or other can write to is now refused with a non-zero exit before anything is downloaded, a directory the current user does not own is reported as a warning, and the staged file is created new under a name this install invents, so an entry already sitting at that name is left untouched.
