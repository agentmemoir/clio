Clio now opens the encryption key file once, without following a symbolic link, and judges and reads the file from that same open: a local process with write access to the key directory could previously swap the file between the permission check and the read, so Clio used bytes that process chose, and a symlink placed at the key path was followed. A key file that is a symbolic link, is not a regular file, is owned by another user, or grants access to group or other is refused with the path and the reason. The real, named directory holding the key file is made owner-only on read and on write, and a directory that cannot be made owner-only is refused. A symlinked key file is refused, so point the key path at the real file; a symlinked key directory is refused, so use a real directory; a key file or directory owned by another account is refused, so make it owned by the user Clio runs as.
