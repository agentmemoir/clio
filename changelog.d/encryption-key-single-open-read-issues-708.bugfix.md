Clio now opens the encryption key file once, without following a symbolic link, and judges and reads the file from that same open: a local process with write access to the key directory could previously swap the file between the permission check and the read, so Clio used bytes that process chose, and a symlink placed at the key path was followed. A key file that is a symbolic link, is not a regular file, is owned by another user, or grants access to group or other is now refused with the path and the reason, and the directory a key file is written into is made owner-only first, so the key never sits in a directory other users can enter.
