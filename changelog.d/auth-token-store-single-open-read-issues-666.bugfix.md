Clio now opens the auth token store once, without following a symbolic link, and refuses it unless the file it opened is a regular file owned by the running user and readable only by that user: a local process with write access to the config directory could previously swap the store between the permission check and the read, so Clio loaded bytes that process chose, and a symlink placed at the store path was followed. A store that is a symlink, is not a regular file, is owned by another user, or is readable by group or other is now refused with the path and the reason, and a missing store is still an empty one.
