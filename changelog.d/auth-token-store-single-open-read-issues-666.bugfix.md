Clio now opens the auth token store once, without following a symbolic link, and checks the file it actually reads: a local process with write access to the config directory could previously swap the store between the permission check and the read, so Clio loaded bytes that process chose, and a symlink placed at the store path was followed. A store that is a symlink, is not a regular file, or is readable by group or other is now refused with the path and the reason, and a missing store is still an empty one.
