A sync push can now record an erasure denial only when the presented token's actor is `harness` or `system` and the token reaches every bank the carrier covers. The gate runs on the content the apply path reads, so it covers a sealed carrier as well as a plaintext one: a sealed carrier is opened by the serving peer and refused before it writes any subject denial, bank marker, or journal row. Before this change, any bank-scoped token could durably refuse an arbitrary subject for every bank on the node, and that refusal could not be removed. A node that delivers denials to a peer must present a token created with `clio auth token add --actor harness` (or `system`); a carrier from a token with another actor, or one covering a bank the token cannot reach, is rejected and quarantined in the dead-letter queue. Two limits remain: a server with no credential store (dev mode) accepts an unbound request, and a pull carries no credential from the serving peer. A carrier received through a pull is therefore recorded only when the configured peer is trusted for destructive operations, through the new `sync.trust_erasure_carriers` setting or `CLIO_SYNC_TRUST_ERASURE_CARRIERS`; both default to false, and a carrier from an untrusted peer records nothing and is quarantined in the dead-letter queue.
