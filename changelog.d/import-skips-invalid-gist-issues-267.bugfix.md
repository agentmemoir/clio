An import now reports the entity id and skips an entity whose stored gist exceeds the published length limit, instead of aborting the whole bundle: every other entity in the bundle still applies, and the report lists what was skipped and why. An import that restores nothing because the target bank already holds every entity now says exactly that, with the skipped count, instead of printing a zero-create line that reads like a successful restore.
