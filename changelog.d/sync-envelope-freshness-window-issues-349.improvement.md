A new operator setting, `sync.max_envelope_skew_secs`, refuses a pulled or pushed sync envelope whose sealed `transaction_time` sits more than the given number of seconds behind the applying node's clock, or more than an hour ahead of it, so a node that never journaled a mutation id can no longer apply that mutation's replay and a fast clock cannot win every later merge. The setting defaults to `0`, which turns the age bound off and leaves every envelope eligible, because a wall-clock bound cannot tell a replay from a legitimate backlog — a node that was offline for longer than the window — and refusing that backlog loses the write. Set it to a window comfortably larger than your longest expected offline period, or leave it off. A refused row is never applied and never journaled: both routes quarantine it under `stale_envelope`, or `malformed_stamp` for a stamp this build cannot place, the pull path advances its cursor past it, the serve push route reports it rejected instead of accepted, and `clio sync status` shows a per-bank `stale_refused` count and the last `last_stale_refusal` line. `CLIO_SYNC_MAX_ENVELOPE_SKEW_SECS` overlays the setting from the environment.
