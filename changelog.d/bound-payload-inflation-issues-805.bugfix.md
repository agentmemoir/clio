Before this change, archive verify and restore staged the payload member — inflating and hashing it — and only then compared its digest, while accepting any declared member size up to the most a ustar size field can hold, so a crafted archive could make either command inflate and hash up to 64 GiB minus 1 bytes into the staging directory before the digest rejected it.

A payload declared larger than 8 GiB minus 1 — the largest size a ustar header can encode — is now refused before any of it is staged: the manifest's recorded `payload.bytes` is checked as the manifest is validated, and the container reader stops at a member whose declared size is over that ceiling, so at most 8 GiB minus 1 bytes can be inflated before the digest check runs. The inflation itself still happens before the digest is compared; what is bounded is how much of it a crafted archive can ask for.
