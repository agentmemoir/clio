A `tool_invoke` call for a target the active profile or `--tools` selection does not advertise is now refused with `-32602` and the message ``unknown tool `<name>` `` instead of dispatching, so a restricted profile no longer leaves hidden tools reachable through the wrapper, and a hidden target reads exactly like a name nothing binds.

That refusal also changed shape. Before this change an unbound or hidden target came back as a normal `tools/call` result carrying `isError: true` and the text `` `<target>` is not a tool this build binds ``. It now comes back as a JSON-RPC protocol error with code `-32602` and the message ``unknown tool `<target>` ``, the same answer a direct `tools/call` returns for that name, so a client must read the error channel for this case rather than the result body. The wrapper's own refusals, such as its refusal of a discovery name or of arguments that fail its contract, keep the in-band result they had.
