Operators can now run the local subject-request workflow from the CLI and the MCP stdio surface. The `compliance` commands `request-start`, `request-status`, `request-retry`, `request-copy`, `request-exception`, `request-events`, and `request-close`, and the peer commands `peer-status`, `peer-retry`, and `peer-disposition`, bind to one immutable request id and subject scope. Each report shows technical completion, the pending operator actions, and the request outcome as separate fields, and a wrong scope, actor, or open path refuses before any effect. The protected `erase` command now routes through the same durable request service, so a caller can no longer bypass scope, events, journal, or confirmation.
