A backup prune now holds the resolved backup directory open for the whole run and removes only bare file names in it, so a local user with write access to the backup directory can no longer use a symbolic link or a `..`-bearing path to make Clio delete a file outside it: before this, containment was decided by comparing path spelling alone, and a backup directory that could not be resolved fell back to the raw path. On unix the entry is now inspected once with a single `statat` that does not follow a link, confirmed again by device and inode immediately before the `unlinkat`, and only then removed; a name that changed in between is refused with nothing removed, and bytes are credited only after the unlink succeeds, from the size the inspection saw. A candidate whose parent no longer resolves to that directory is reported as outside the backup directory, and a backup directory that cannot be resolved or opened is reported and removes nothing. Other platforms keep the earlier path-based sequence.
