Sync now puts one encoding of a mutation's transaction time on the wire, canonical UTC text at whole seconds such as `2026-01-01T00:00:00Z`, whatever legend the stored column carried, and it compares two stamps by the instant they name rather than by their text. Two writes one second or more apart therefore order by the instant each names; two writes inside the same second tie at the whole-second precision the wire carries, and a tie is resolved by the origin admission score and then by device id, so neither writer is promised the win. The idempotency key is derived from the same canonical text as the stamp, so a peer can recompute either from the other. For a row whose stored stamp was not already canonical (epoch millis, a bare date, a fraction, or an offset zone), the mutation id and the wire stamp both move once, on the first push after this change; a peer that already holds that row under the old key sees it once as a mutation it has not seen and re-applies the same content, so the stored content, its digest, and the instant the stamp names are unchanged and only the key and the stamp text are.
