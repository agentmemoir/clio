`clio triple end` run in the same second the triple was added now closes the interval one second later than it started, instead of stamping both ends with the same second. A triple closed at its own start used to describe an empty transaction interval and vanished from transaction-time reads, so an assertion the bank had made looked as though it had never been made; it now stays readable up to its close. A close stamped later than the row's start is written exactly as given, and rows already stored are unchanged. A row closed in the same second as it was asserted now stays readable for that closing second, alongside the successor that replaced it.
