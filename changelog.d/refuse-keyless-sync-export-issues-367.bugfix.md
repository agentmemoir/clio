`clio sync push` on a node with no sync key now refuses the export instead of sending memory payloads in the clear: the push fails with a configuration error that names the missing key and the `clio sync keygen` remedy, so an unencrypted transport never carries memory content. A node that holds a key is unchanged, and `sync status` on a keyless node still reports `encryption: false` without an error. Sending unsealed content is now an explicit opt-in for local development and tests through the `allow_plaintext` field of the sync client configuration, which has no command-line switch because a relay refuses every plaintext row it is sent.
