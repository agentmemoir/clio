`tool_invoke` now calls any tool in the catalog by name and returns that tool's result unchanged, so a client that found a tool through `tool_search` or `tool_describe` can run it without a second round of tool discovery. It takes the target's name and the same arguments a direct call takes, refuses `tool_search`, `tool_describe` and `tool_invoke` itself so a wrapper cannot recurse, and counts only the tool that actually ran. The wrapper answers the ordinary unknown-tool refusal until the deployment enables discovery with `mcp.discovery`.
