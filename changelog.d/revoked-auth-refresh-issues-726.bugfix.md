A revoked auth credential could keep working: when the stored credential file changed while a request was being authorised, the reload published whatever it had read, so a credential removed during that read was written back into memory and went on authenticating requests until the file changed again. A reload now takes its records only from a snapshot of the store that did not move, retries a bounded number of times when the file keeps changing underneath it, and fails closed with an authentication error instead of continuing on credentials it could not read consistently.
