The `subject_request_close` tool, the `compliance request-close` command, and the request apply path now require a harness or system caller acting in the request's own bank: an agent, user, or unbound default caller is refused with `forbidden`, and a harness or system caller naming a request in another bank is refused too, with the refused attempt recorded in the caller's audit trail. The `SubjectRequestEnv` type gained an `audit` field, so a caller that builds it as a struct literal must pass the store handle the refusal is recorded through. [Issue #676](https://github.com/agentmemoir/clio/issues/676)
