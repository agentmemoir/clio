Importing a bundle is now limited to an administrative credential on every MCP transport and reports every unreadable local source with the single refusal `bundle source is not a readable bundle file` instead of naming the reason, so a caller bound as an `agent` or `user` is refused before any path is opened and nobody can use the difference between "no such file", "not a regular file", "over the size limit", "not valid UTF-8", and "invalid JSON" to learn what exists on the host filesystem outside the bundle it was given. An operator who could previously tell a missing path from a malformed one now gets one message for both; check the path you passed and that it is a JSON bundle written by `clio export`, and run the import with a `harness` or `system` credential.
