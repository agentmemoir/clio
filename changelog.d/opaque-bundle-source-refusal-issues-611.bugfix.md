Importing a bundle from a local source path now reports every unreadable source with the single refusal `bundle source is not a readable bundle file` instead of naming the reason, so a caller can no longer use the difference between "no such file", "not a regular file", "over the size limit", "not valid UTF-8", and "invalid JSON" to learn what exists on the host filesystem outside the bundle it was given. An operator who could previously tell a missing path from a malformed one now gets one message for both; check the path you passed and that it is a JSON bundle written by `clio export`.
