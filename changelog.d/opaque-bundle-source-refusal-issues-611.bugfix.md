Importing a bundle over MCP now requires a harness or system (administrative) credential whenever the connection is bound to a principal, so a caller bound as an `agent` or `user` is refused with `bundle import` named in the message before any path is opened; a local, unbound stdio state still imports, because the process owner already holds the store. Bundle-source errors now expose only coarse, non-identifying categories — one refusal for every unreadable or non-regular file, a separate one for a source over the size cap, and a separate one for text that is not JSON — instead of naming the underlying reason, so a caller cannot use the difference between "no such file", "not a regular file", "not valid UTF-8", and an I/O failure to learn what exists on the host filesystem outside the bundle it was given. An operator who could previously name the exact failure now gets a category: check the path you passed and that it is a JSON bundle written by `clio export`, and run the import with a `harness` or `system` credential.
