The gate writes its published verdict under one lock on the published directory and replaces each file in a single step, and it writes the exit code first, so `logs/<kind>.exit` and `logs/<kind>.log` always describe one run, with the run they replaced still readable as `logs/<kind>.prev`: a run that cannot write its exit code publishes nothing, and two worktrees sharing `CLIO_GATE_LOG_DIR` can no longer pair one run's log with another run's exit code. Each published log also carries a `gate: run ...` line naming the worktree, the tree fingerprint, and the finish time of the run the record describes, so a verdict published by another worktree or by an older replay can be told from the reader's own.
