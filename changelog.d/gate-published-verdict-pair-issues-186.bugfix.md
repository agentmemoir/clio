The gate writes its published verdict under one lock on the published directory and replaces each file in a single step, and it writes the exit code first and puts it back if the log cannot be written, so the published pair is either the newest run's or the run that was already published; a run that cannot write its exit code publishes nothing, and two worktrees sharing `CLIO_GATE_LOG_DIR` can no longer pair one run's log with another run's exit code. Each published log, and each published `logs/<kind>.exit` after its exit code, carries a `gate: run ...` line naming the worktree, the tree fingerprint, and the finish time of the run the record describes, so a verdict published by another worktree or by an older replay can be told from the reader's own; the run a newer one replaced stays readable as `logs/<kind>.prev`.
