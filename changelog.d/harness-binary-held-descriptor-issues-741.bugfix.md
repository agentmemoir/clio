Clio now opens a harness binary once, judges that opened file, and starts the vendor command from the same file, so a local process that can write to a directory on `PATH` can no longer swap the binary between the check and the exec and run its own code as you: before this, the check inspected a path and the spawn resolved that path again, and on Linux the held descriptor is what the kernel starts while the original path stays the visible program name. On macOS and the BSDs, where a program cannot be started from a held descriptor, Clio holds the canonical executable path and refuses it unless every directory above it is owned by root or you and is not writable by group or other, so another user cannot replace the named file; other platforms keep the earlier path-based lookup.
