A discrete update now stores the value it was given. `clio update <id> "<new value>" --rule discrete` closes the old item and writes the new value onto a replacement item, and the closed item's invalidate event names that replacement, instead of reporting success with `replacement_id: null` while the value was silently discarded. A discrete update that cannot store anything — the item is already superseded, the target does not exist, the value is blank, or the target is a belief that only evolves through `belief_observe` — now fails with an error rather than reporting success.
