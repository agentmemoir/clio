A backup now refuses to write over an existing name, or into a `backups/` path that is a symbolic link or not a directory, so a planted entry is left in place instead of being followed or truncated. The backup file is created exclusively and owner-only, so any entry already at the target name is never followed or truncated. A `backups/` directory must be a real directory beside the config file; a symbolic link is not supported. To keep backups on another filesystem, move the config directory there, or copy the file yourself before saving.
