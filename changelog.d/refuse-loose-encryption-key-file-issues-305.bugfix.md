Clio now refuses to use an encryption key file that grants any access to group or other, applying to that file the same owner-only rule the sync key file and the auth token store already enforced: any command that needs the key stops with "encryption key file <path>: refused because it is not owner-only; restrict it to the owner (0600) and run again". Before this, a 32-byte key file at mode 0644 was read and used, so any local account that could read the file could decrypt every value sealed under that key. Restricting the file to the owner and running the command again resolves it; an owner-only key file and a missing one behave exactly as before, and no key is regenerated, moved, or rewritten.
