`clio batch --file -` and `clio hygiene clean --file -` now read at most 8 MiB from stdin and refuse a larger document with a usage error naming the cap, instead of letting a pipe writer grow the process's memory without bound before the JSON is parsed; a document exactly at the cap still reads whole, and the alternative the error names is to split the document across more than one run. Only the `-` (stdin) form is capped: a `--file PATH` argument names a file the operator chose, so its handling is unchanged.
