A sync client pull is now bounded instead of trusting the peer to stop it. Before this change the pull loop fetched page after page as long as the server answered `has_more`, so a misbehaving or hostile peer could keep one pull running without end. The loop now stops with an error after a fixed page cap (1000 pages), and it stops with an error as soon as a page hands back a cursor this pull already used, whether that is the cursor the page was asked from or any cursor an earlier page of the same pull handed back: a peer that reports more rows but does not advance the cursor, or that flips back and forth between two cursors, would otherwise serve the same pages forever. Every page still persists its cursor, so a legitimately larger backlog resumes from the stored cursor on the next pull.
