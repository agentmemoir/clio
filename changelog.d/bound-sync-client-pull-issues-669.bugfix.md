A sync client pull is now bounded instead of trusting the peer to stop it. Before this change the pull loop fetched page after page as long as the server answered `has_more`, so a misbehaving or hostile peer could keep one pull running without end. The loop now stops with an error after a fixed page cap (1000 pages), and it stops with an error as soon as a page hands back the cursor that page was asked from: a peer that reports more rows but does not advance the cursor would otherwise serve the same page forever. Every page still persists its cursor, so a legitimately larger backlog resumes from the stored cursor on the next pull.
