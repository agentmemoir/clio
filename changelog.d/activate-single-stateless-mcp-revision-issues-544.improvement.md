The MCP server now serves exactly one protocol revision, `2026-07-28`, over a stateless transport: every request carries its own version header and metadata, no handshake is required, and the server mints no session id, so `clio mcp http` no longer accepts `--sessions` and a client that sends `initialize`, `notifications/initialized`, or an `MCP-Session-Id` header gets the stateless refusal instead of a session.
