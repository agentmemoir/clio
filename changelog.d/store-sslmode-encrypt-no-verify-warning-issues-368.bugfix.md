Opening the Postgres store with `sslmode=encrypt-no-verify` now logs a startup warning, unless the process log level is above `warn`, saying that the connection is encrypted but the server certificate is not validated, so any host that can intercept it can impersonate the database, and names `sslmode=verify-full` with `sslrootcert=PATH` as the safe alternative; the four accepted `sslmode` values and this warning are now documented in the compliance operator runbook.
