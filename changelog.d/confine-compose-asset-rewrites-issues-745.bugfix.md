`clio compose up` now opens each materialized compose asset once, without following a symbolic link, and reads, backs up, and rewrites that one held file: a local process with write access to the compose root could previously swap the file, or a parent directory, between those steps, so Clio read one file, backed up another, and wrote a third through a path that escaped the root. A symlinked asset or parent component is now refused, a mount source that is a symlink no longer satisfies the bind-mount check, and a name that changes under the held file stops the run instead of overwriting the replacement. [Issue #745](https://github.com/agentmemoir/clio/issues/745)
