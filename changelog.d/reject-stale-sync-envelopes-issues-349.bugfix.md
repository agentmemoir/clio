A sync envelope is now refused as stale when its authenticated `transaction_time` sits further from the applying node's clock than the freshness window allows, in either direction, so a stamp the node cannot place is no longer applied. The refusal reports `stale`, writes nothing, and advances the pull cursor past the row instead of freezing that bank. The window is `sync.max_envelope_skew_secs`, `300` seconds by default, and the serve push route and the pulling client both read that setting, so the rule applies on every shipped path; `0` turns it off.
