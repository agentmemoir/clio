A PostgreSQL connection string that names no `sslmode` now asks for TLS with full certificate verification when any host it names is not on this machine, whether that host comes from the authority, the query `host`, or `hostaddr`; a loopback-only list, a Unix socket, and an empty host list keep the old preference for an unencrypted local server. An explicit `sslmode` still wins over that default, and the driver mode is set on the parsed configuration instead of being appended to the string. The setup wizard now treats a mixed host list as remote, so a mode stored for this machine cannot override a remote address. The setup probe reports the client's TLS policy separately from the TLS leg the server reports for its own peer.
