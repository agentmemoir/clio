A node with no sync key now refuses to push, pull, or run a bidirectional transfer instead of packaging its memory as plaintext: the error says sync on this node has no sync key, that memory is never synced without client-side encryption, and to run `clio sync keygen`. `sync_status` and `sync_key_status` still answer on such a node, so an operator can see the missing key before recording one. A node with no sync key also refuses to apply a plaintext row it pulls, quarantining it as unauthenticated instead of writing it to memory. A serving node now refuses a plaintext row a peer pushes at it, quarantining the row and listing it in the acknowledgement as rejected with reason `malformed`.
